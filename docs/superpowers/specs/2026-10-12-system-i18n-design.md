# 系统中英文与语言配置设计

状态：用户已于2026-10-12明确确认，授权实施。

## 目标与范围

支持简体中文 `zh-CN` 和英语 `en-US`，默认保留中文。覆盖系统自身的界面、授权说明、状态、任务阶段、结果、操作反馈、错误提示及命令行帮助。

| 入口 | 配置与切换 | 保存方式 |
|---|---|---|
| A 端网页 | 登录页与工作台提供“简体中文 / English”选择；配置页提供界面语言设置 | 当前浏览器的本地设置 |
| B 端 Windows GUI | 窗口提供语言选择；支持启动参数与 JSON 配置 | 当前用户的 Worker 设置文件 |
| B 端 TUI | 支持启动参数与 JSON 配置；F2 打开语言选择 | 当前用户的 Worker 设置文件 |
| B 端 plain | 支持启动参数与 JSON 配置；普通提示/连接后支持 `lang zh-CN`、`lang en-US` | 当前用户的 Worker 设置文件 |
| Controller / MCP 命令行 | 同样支持语言参数与 JSON 配置，翻译帮助及系统自身的启动/操作提示 | 各程序自己的用户设置文件 |

A、B 的语言各自选择，不通过远程会话强制同步。A 网页设置仅作用于当前浏览器；Controller 的命令行语言仅作用于该进程的本地提示。

软件名、固定版本、设备名、用户输入、URL、任务 ID 和安装器/操作系统原始日志保持原值。系统提供对应语言的说明与诊断入口，不尝试机器翻译外部日志。Windows UAC 系统窗口使用 Windows 自身的语言。

## 方案选择

1. **采用：统一词条与配置解析，Go 和网页共用中英文词条资源。** 通过稳定词条键生成文本，便于核对翻译完整性，避免 GUI/TUI/plain 各自翻译同一阶段。
2. 只替换界面中的中文字符串：改动较少，但运行中切换、缓存通知和错误信息容易漏译。
3. Go 与网页分别引入大型国际化框架：功能更丰富，但当前两种语言用不到其多数能力，增加依赖及两套词条维护成本。

不增加第三方国际化运行时，继续支持无 CGO 的便携 Windows 客户端。

## 配置规则

原生命令行入口统一增加：

```powershell
.\remoteops-worker-windows-amd64.exe --lang=en-US --pairing .\pairing.json
.\remoteops-worker-windows-amd64.exe --ui=plain --config .\client-settings.json
.\remoteops-worker-gui-windows-amd64.exe --lang=zh-CN
```

语言配置文件：

```json
{
  "language": "en-US"
}
```

优先级：`--lang` → `REMOTEOPS_LANG` → `--config` 指定文件 → 当前用户已保存设置 → `zh-CN`。配置文件和保存文件使用相同格式；语言选择只保存语言字段。

默认设置目录使用 Go 的 `os.UserConfigDir()`，其下建立 `RemoteOps` 子目录；Worker、Controller、MCP 分别使用 `worker-settings.json`、`controller-settings.json`、`mcp-settings.json`。Windows 通常位于 `%APPDATA%\RemoteOps\`。

显式参数、环境变量或显式配置文件包含不支持的语言/无效配置时，在联网前给出清晰错误。隐式用户设置不可读或损坏时使用中文，显示可恢复提示。语言保存失败只影响记忆功能，本次切换仍生效。

从界面选择语言会立即更新当前界面并保存。启动参数/环境变量只覆盖当前进程，不静默改写已保存偏好。指定 `--config` 时，界面保存回该指定设置文件；未指定时保存到默认用户设置文件。保存采用同目录临时文件及原子替换，保留已有文件直到写入成功。

网页在读取本地偏好失败时仍可选择语言，显示保存失败提示；默认中文。切换时同步更新页面标题、HTML `lang`、日期/数字格式及无障碍标签。

## 运行中切换与授权

- 切换语言只更新显示，不修改会话、审批、软件目录、任务参数或执行状态；已连接会话继续运行。
- 连接前切换语言时重新呈现完整授权摘要，并清除尚未提交的勾选与密钥，让用户按新语言明确确认。
- TUI/plain 正在读取密钥时不把输入解释为语言命令或快捷键；密钥持续遮罩且不回显。Ctrl+C 仍可立即断开退出。
- TUI 继续使用 Y/N 明确同意/拒绝。plain 使用所选语言的完整确认词：中文“同意”，英语“AGREE”；回车不能默认授权。
- GUI 保留原生控件、稳定控件 ID、键盘操作与焦点保护。语言切换在 UI 线程重绘，不阻塞网络/任务线程。
- 保留任务的稳定 ID、20/100 项上限、执行中任务优先保留、所选任务取消和长日志阅读位置。

## 文案与数据边界

新增共享词条资源和小型本地化服务，按程序/页面命名词条。两种语言的键与参数占位符必须对应，未知词条显示安全的通用提示并在开发测试中报告缺失。

共享客户端在生成快照时使用当前语言呈现授权范围、通知和错误。内部保留必要的无凭据结构/错误类别，不依赖对已生成中文字符串做反向替换，也不为切换语言重新获取或保存密钥。任务标题、阶段与结果通过同一展示服务供 GUI/TUI/plain 使用。

API 状态值、任务类型、错误码、JSON 字段、签名内容及 MCP 工具名/参数保持稳定。网页按错误类别生成对应语言提示；未知错误保留诊断标识，使用对应语言的通用说明。MCP 的 stdout 仍仅输出协议消息。

展示参数继续脱敏并去除控制字符。翻译资源是随程序交付的本地文件，不下载远程翻译、不增加凭据配置。语言文件仅包含语言，不保存 Auth Key、管理令牌或会话凭据。

## 验收

1. 配置优先级、保存后重启、损坏配置、非法语言和保存失败都有真实文件/解析回归；测试使用独立临时目录，不修改本机真实偏好。
2. 词条完整性及参数一致性通过自动检查；中英文分别覆盖授权、连接、任务阶段、结果、取消、断开、到期、失联和错误。
3. 中文/英文网页覆盖登录及五个视图，验证切换和刷新后保存、日期格式、可访问名称及窄屏布局；保留原配对下载、焦点和表格操作功能。
4. GUI 在最小 720×560 及既有 DPI 条件下验证英文长文本、语言选择、完整授权、密钥遮罩、键盘操作及日志位置。
5. TUI 在 60×18、100×30 验证两种语言；plain 验证对应确认词、遮罩、语言命令、稳定取消编号与退出。
6. helper 在任何 UI/语言设置初始化前分流，继续拒绝混合参数；Controller/MCP 的语言参数不得影响凭据或协议输出。
7. Go test/race/vet、网页测试/typecheck/build通过，重构并核对 Windows Controller、Worker GUI/TUI、MCP 产物和摘要。
8. 保留主目录现有未提交改动及其功能。所有界面/任务验收使用惰性模拟，不启动真实会话、不安装软件、不执行真实 UAC 决策、不停启已有进程。

## 实施顺序

先实现词条及配置服务，再接入 B 端共享展示和三种界面、A 端网页及其余命令行，最后完成双语界面验收、构建、审查和保留原工作区改动的本地整合。按已确认设计编写实施计划并持续执行。
